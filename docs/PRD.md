# Akma — MVP product definition

## User problem

A student or professional receiving a job invitation, client request or work message must switch to a cloud chatbot to draft an appropriate response. Akma enables explicit, private, offline reply drafting next to that conversation.

## Single core journey

1. User manually copies a synthetic HR message in Viber or another tested messaging app.
2. User opens assistant overlay after granting overlay permission.
3. User pastes the message into a focused input (no background clipboard read).
4. The app offers at most three relevant actions from the reviewed seven-category local catalog. Classification provenance is explicit; deterministic presets are not described as LLM classification.
5. User selects an action (e.g. **request reschedule**) and professional tone, then explicitly confirms that action and tone before drafting.
6. **The phone's local AI model** generates an editable, faithful draft; it must not invent availability or a replacement time.
7. User edits/copies the draft and manually pastes it back; no auto-send.
8. Demonstrate a different text produced with mobile data and Wi-Fi disabled after model provisioning.

## Must-haves

- Onboarding and permission recovery; Activity fallback if overlay fails.
- Reliable user-paste path, required nonempty input and length cap.
- Explicit action selection, separate human confirmation for every action, and local generated draft.
- Clear loading/error/timeout/no-model states and duplicate request prevention.
- Editable draft and manual clipboard copy.
- Android 11 compatibility on Tecno Pova 2, then Android 14 smoke test on Camon 30.
- Real offline inference evidence, reproducible setup, model attribution, public repo and 60-second working-demo video.

## Stretch — only after proof and integration

- More tones, application share-text intent, floating bubble dragging, UI animations, a second supported messaging app.

## Never promise in MVP

- Full InputMethodService keyboard, automatic message scraping, AccessibilityService, notification capture, sending without consent, zero-click workflow, remote inference fallback, iOS, accounts, RAG or analytics.

## Acceptance examples

**HR:** “Are you free Friday at 10?” + Reschedule → polite alternative request without invented new availability.

**Complaint:** “Your delivery was late.” + Apologize → no promised refund.

**Deadline:** “Can you finish tonight?” + Clarify → does not commit to finish.

All examples are synthetic and must be generated by the model at runtime for the actual demo; recorded static outputs must not be mislabeled as AI.
